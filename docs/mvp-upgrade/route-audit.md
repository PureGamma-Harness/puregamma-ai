# PureGamma MVP route audit and independent review brief

Audit base: `48fe3154fe56a0640d08148f0c7eaf7825af2da7`. This is a source-based baseline audit, followed by explicit candidate review records below. It is not a claim that all routes or providers were browser tested or production enabled.

## Execution prompt for this workstream

**Role:** independent product, route, accessibility and Agent SaaS contract reviewer. **Context:** Next.js App Router/React19 web, FastAPI, user-owned Agent conversations and memory, capability-gated Harness research, financial stale-state rules, PAPER/SHADOW control and separately gated LIVE. Read the actual page, primary component, API helper and middleware before recommending a change.

**Task:** inventory every page route; separate localized canonical routes, route groups, aliases, external provider prerequisites and default-hidden surfaces. Evaluate the user's end-to-end action, not only whether JSX renders. Review each implementation workstream against its written prompt, tests and actual diff. Use React/App Router progressive loading/error recovery, WCAG2.2 keyboard/focus/status semantics, retrievable source provenance and bounded tool execution where those mechanisms fit the existing contract. Do not add RAG to ordinary account forms or call a framework upgrade a product improvement.

**Constraints:** preserve en/zh, Glass/Classic, light/dark and reduced motion. Never convert unavailable financial data to a valid zero, swallow a mutation failure as success, infer authorization from a visible route, elevate memory to trading permission, create real payments/trades/tunnels/messages, enable providers/LIVE, or deploy. Independent review owns documentation and scratch probes only; product changes belong to the implementation workstreams. Keep dependency and credential handling unchanged.

**Definition of done:** all90 page files are accounted for; every canonical route has a primary view/API, access/capability boundary, user action, source-assessed state and an actionable MVP acceptance expectation. High-priority findings have exact source evidence and owners. Candidate reviews distinguish source review, offline behavior tests, real browser checks and untested external-provider boundaries. No success claim is made from a static inventory alone.

## Inventory and reachability

- **90 page files**: **54 localized canonical routes**, **33 legacy alias pages**, **1 root locale redirect**, and **2 public legal pages**. `(auth)` is a route group, not a URL segment. Dynamic conversation/run/strategy IDs denote route patterns, not a finite number of records.
- Both locales are `en` and `zh`. A count of page files is not a count of independently usable product features.
- `REQUIRE_AUTH=true` applies the shared `requiresAuthentication` route list. Middleware only checks that a session cookie is present; server APIs remain responsible for validity, role, ownership, entitlements and capabilities.
- Default `NEXT_PUBLIC_INITIAL_LAUNCH_MODE !== "false"` redirects `/signals`, `/playbooks`, `/strategies`, `/trading`, `/nautilus`, `/data-sources`, `/integrations`, `/daily-push` and `/billing/mock-checkout` (and descendants) to the localized dashboard. These rows carry **H**. Auditing them with an explicit local full-product environment does not authorize production enablement.
- Baseline contains **no `loading.tsx` page-segment fallback** and only `secretary/error.tsx`. Component busy/error displays are not a substitute for every server-route failure. Root owns the proposed locale loading/error fallback.
- `P` means the shell is public, **not that a backend mutation is public**. `A` means listed in authenticated middleware when auth is required. `admin` additionally uses `AdminGate` and server role checks. The API column names the actual frontend helper or direct literal path. Helpers are defined in `apps/web/lib/api.ts`; their `/api` prefix conventions vary, so this table intentionally does not invent a normalized HTTP endpoint specification.

## Common MVP acceptance checks

Each canonical row uses the following common checks in addition to its named action: initial loading is distinguishable from empty content; request failure and permission denial are distinguishable and recoverable; errors do not claim a successful write; selected values survive the intended retry/back/refresh flow; data provenance/date and stale/unknown states remain visible; all controls have persistent accessible names and visible focus; keyboard navigation has no hidden/focus-trapped background items; mobile390px has no unintended page-level horizontal overflow; en/zh and both visual themes remain coherent. Optional-provider and read-only/disabled states must be explicit. A route can satisfy the unavailable-state contract without its optional provider being configured.

**Evidence level at baseline:** every row below is inspected in source (**S**). Full-route desktop/mobile/browser and mutation validation are **pending candidate-specific verification**, not asserted by this audit. Existing upgrade smoke has a limited route set and cannot establish all90 page files' behavior.
